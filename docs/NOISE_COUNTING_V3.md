# 新计数算法检测包（1.2.2.0.3）

本次代码优化由 OpenAI Codex 编写。该版本继承 1.2.2.0.2 的内存、走秒和界面修改，替换吵闹事件的归属算法。

## 对照旧包，避免重复旧设计

| 旧版 | 查到的实现 | 本次避开的问题 |
| --- | --- | --- |
| 1.0.0.1 | 发布说明为等级触发加冷却；标签源码的冷却实际为 3 秒，与说明的 60 秒不同 | 不依赖瞬时等级跳变触发次数，也不恢复冷却 |
| 1.0.1.0 | 等级触发、可调冷却（默认 60 秒），一般事件在 30 秒内可改记吵闹 | 不先增加计数再减去改记，也不限定只能在前 30 秒升级 |
| 1.0.1.1 | 实际包 DLL/PDB 与标签一致：默认持续 1.5 秒时按当时占比定格，分等级冷却 | 不在起算时提前定格为一般，后续吵闹仍可升级 |
| 1.0.1.2 / 1.0.1.3 | 1.0.1.2 实际包采用段结束后按整段占比归属、无冷却；对应 1.0.1.3 标签源码 | 不用整段比例，延长一般时间无法冲淡已经满足的吵闹证据 |

核验方式：对照 Git 标签源码、Release 说明，下载 1.0.1.1/1.0.1.2 的 `.cipx`，读取 DLL 字段和 portable PDB 的源码 SHA256。1.0.1.1 检测器源码 SHA256 为 `940ac483b3ddb877a55da9de63754037148ca0169230fada58f7b6d3b85ecc72`；1.0.1.2 包内为 `e6c83fa47e9b457c521136ef30c53bac8381776daf0b49fe587f5fb9955ae0f1`，后者匹配 1.0.1.3 标签而非 1.0.1.2 标签，不能仅凭标签判断旧包算法。

## 本包规则

1. 保留 EMA 平滑、迟滞分级，以及可调起算底线（默认 1 秒）和回落窗口（默认 5 秒）。
2. **连续处于吵闹档 5 秒，或最近 10 秒内累计处于吵闹档 6 秒，即锁定本段为吵闹。** 本检测包固定这三个参数，便于比较反馈。
3. 锁定后延长一般时间不再降级；起初一般的长段也能在后来满足条件时升级。瞬时音量档位仍反映当前声音。
4. 连续安静/良好超过回落窗口才结束一段。有效时间达到起算底线时，每段仅结算一次，未锁定的记一般，已锁定的记吵闹；更短的段丢弃。短暂停顿仍合并，无计数冷却。
5. 上课初期保护和课间不计数的既有规则保留。计数到段结束才增加，“正在记录”先显示归属。

最近时间窗按音频块的真实时长裁剪，包括横跨窗口起点的半块；安静和一般时间也推进时间窗，过期证据不能跨长时间累计。证据只保留最近 10 秒的吵闹块，不保存音频，锁定或结束后清空，持续运行不会保存整节课的采样历史。无效 RMS/时长不会污染后续状态。

## 模拟与回归

测试入口：`dotnet run --project tests/NoiseAlgorithm/NoiseAlgorithm.csproj`，直接编译生产检测器和计数器。确定性等级输入使用 0.1、0.13、0.2、0.5、1 秒块长验证分段/边界，另用真实 EMA/迟滞处理合成 RMS 验证端到端归属。

| 合成情景 | 旧整段占比的吵闹次数 | 新算法的吵闹次数 |
| --- | ---: | ---: |
| 单次 0.2 秒高幅拍手 | 1 | 0 |
| 吵闹 8 秒后一般 40 秒 | 0 | 1 |
| 一般 60 秒，再吵闹 8 秒，再一般 40 秒 | 0 | 1 |
| 吵闹 3 秒、一般 2 秒，反复 4 次 | 0 | 1 |
| 0.6 秒短声与一般 5 秒交替 12 次 | 0 | 0 |
| 两次吵闹 8 秒，中间安静 8 秒 | 2 | 2 |

上表来自同一套 EMA/迟滞下的 200ms 合成 RMS 模拟：安静 0.001、一般 0.05、吵闹 0.12、拍手 0.65，并有首尾安静预热/结算。它是规则对比，不是真实教室录音准确率。回归还覆盖先一般后吵闹、锁定后拖长一般、过期证据、窗口首块裁剪、重置、保护、无冷却及两小时段内存边界。

## 真机检测重点

- 吵闹持续约 8 秒后回到一般：提示应保持“正在记录：吵闹”，安静超过回落窗口后只增加一次吵闹计数。
- 先保持一般较长时间再吵闹：仍应正常升级；短暂停顿合并、长暂停顿分开。
- 在设置里开启现有的采样日志开关，按需调整保留条件。CSV 头部会标记 V3 规则，可提供发生时间及该 CSV 用于复核，不会录制声音。

5 秒/6 秒按平滑后的档位计时，与原始发声起点可能有少量延迟；声卡增益和原有音量阈值仍会影响分类。刻意始终低于两个触发条件的声音不会锁定为吵闹（例如每 10 秒仅吵闹 4 秒），该边界需结合实测调整，不能把合成测试通过等同于无法规避。
